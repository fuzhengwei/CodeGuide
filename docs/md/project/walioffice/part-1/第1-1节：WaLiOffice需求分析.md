今天是我们《WaLiOffice - AI Agent 智能办公平台》项目学习的第 1 节，我们先从需求分析开始，理解这样一个项目要做什么、要解决什么场景问题，以及为什么我们要用 Rust + React + AI Agent 这套组合来做。

接下来，我们会按照公司里产品需求立项，分析它的背景、讲述它的功能，罗列它的挑战等，按照日常在互联网公司里，大家所做的事项一，走一个完成流程。

>互联网公司中，一个需求首先是从业务侧发起的盈利目标，拆分为不同的运营策略。再把对应的策略由产品经理设计为可以支撑市场运营操作完成盈利目标的具体项目。所以这里有一般有 3 个角色，包括；业务人员、运营人员、产品经理。他们分别在自己的岗位产生不同的资料，包括；MRD、BRD、PRD。

- 市场需求文档（MRD）：从市场的角度出发，描述目标市场的需求和机会。包括目标客户群、市场趋势、竞争分析、市场机会、产品定位等。
- 业务需求文档（BRD）：更侧重于业务角度，描述业务目标、业务流程、业务规则、业务问题以及业务需求。
- 产品需求文档（PRD）：根据 MRD 和 BRD 中确定的需求，具体描述产品的功能性和非功能性需求。包括用户故事、用例、功能列表、性能要求、界面设计等。

接下来，我们来对本次的《WaLiOffice - AI Agent 智能办公平台》进行需求分析，让大家细致的了解 AI 智能办公的场景业务。

## 一、项目背景

> WaLiOffice 可以用于任何需要快速生成办公文档的场景。《做 PPT》、《写报告》、《出表格》、《画流程图》、《生成配图》、《制作视频》——这类在日常工作里高频但低效的手工操作，就是我们要解决的核心痛点。

在传统的办公流程中，用户需要打开不同的软件（PPT、Word、Excel、Visio、Photoshop、Premiere），手动操作几十甚至上百个步骤才能完成一个汇报或者课件材料。这个过程有几个问题：

1. **工具使用成本高**：做一个汇报材料，你可能要开 4-5 个软件，来回复制粘贴
2. **模板复用困难**：每次都从零开始，上次有排版也要手工删掉内容在编写新的
3. **协作效率低**：需求方说"帮我做个 PPT"，执行方要反复确认风格、内容、格式
4. **创意落地慢**：脑子里有想法，但手上操作跟不上，等做出来“黄花菜”都凉了

所以，这里的产品诉求是；一句话描述需求，AI 就自动帮你生成对应的办公产物——PPT 能预览、Word 能导出、Excel 能下载、流程图能编辑、图片能保存、视频能播放——这就是 WaLiOffice 要做的事。

如图，WaLiOffice 的核心交互模式就是**对话即生产**。用户在对话框里输入自然语言，AI Agent 自动理解意图、选择工具、执行生成、返回产物。整个过程流式反馈，用户可以实时看到 Agent 在"想什么"、"调什么工具"、"做到哪一步了"。

> 你可以把它理解成一个"懂办公的 AI 助手"——你说"帮我做一个季度汇报 PPT，包含销售数据柱状图和团队分工表格"，它就自动拆解任务、调用 PPT 工具和图表工具、把结果拼装好给你。不用你一个个软件去切。
