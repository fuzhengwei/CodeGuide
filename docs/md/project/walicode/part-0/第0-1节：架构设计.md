接下来，我们要开启 **《WaLiCode - AI Coding 智能编码》** 这部分内容的学习。在开始逐个章节的编码学习之前，我们先来整体分析下架构设计。因为这部分内容虽然也是使用 AI Agent 脚手架，但对于比 **《WaLiSSH - AI Shell 智能终端》** 还是有所不同的。这个不同，就是我们要提前说明的事情。

WaLiSSH 使用的 C/S 架构方式，因为本身我们操作云服务器，就是一种远程 SSH 命令的方式进行执行。而且只通过一种标准的 SSH 命令，加上 AI Agent 就可以智能化的操作云服务器。但这种方式放到本地编码就会有蹩脚了。为啥呢？

WaLiCode 本身要执行大量的文件操作；`创建文件`、`写入文件`、`修改文件`、`搜索文件`、`删除文件`以及各类 `Git 操作`等。这些东西远程是没法执行的，而如果把远程的命令通过 MCP 或者其他协议到本地在执行一次，要来回在本地和远程传递消息，效率和准确度都有所降低。

所以，我们这里小傅哥设计了另外一个方式；把 `walicode-server` 服务端，打包成 Jar 放到客户端里，并加入 java 运行时最小 jvm。这样就天然的让 `walicode-server` 服务端，可以在本地执行各类工具了。

```pom
    <scope>compile</scope>

```

> 在 AI 时代，架构设计、场景方案、模型设计，都显得更为重要。把这些东西定义清楚，那么 AI 编码就变得更加准确可靠了。并且像是 AI Agent 这东西，一个语言学会了，其他语言也都一样。只是我们需要用最熟悉的语言，采用最合适的架构，把这些东西学习下来。

## 一、本章诉求

WaLiCode 是一个基于 Tauri（打包桌面） + React（客户端） + Java（运行时 Agent Jar） 的 AI Coding 智能编码桌面应用。核心能力包括：本地工作区代码理解、AI 对话编码、工具调用执行、代码补丁审批与回滚、SSH 远程服务器管理（`我们把这个也包进来`）等。

本节要解决的诉求是：

1. **了解整体架构**：客户端（Tauri/React）与服务端（Spring Boot DDD）分别承担什么职责、如何分层。
2. **知道工具链路**：用户发出一句话后，"意图识别 → 提示词组装 → LLM 决策 → 工具执行 → 结果回传"这条 ReAct 循环是如何跑通的。
3. **升级架构版本**：对 AI Agent 脚手架创建的初始化工程，进行版本升级。`SpringBoot 4.x`、`Google ADK 1.10.1`、`Spring AI 2.0.1`，这里还涉及了一些代码上的变动（新旧版代码差异）。
